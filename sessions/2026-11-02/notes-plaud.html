Summary

Daniel Chen introduced a course sequence on data processing in R, covering data cleaning and transformation, visualization, modeling, and communicating results. The lectures emphasized tidy data: how to identify and reshape messy datasets, preserve information in analysis-ready form, and use Tidyverse tools for data manipulation and visualization. They also introduced regression and classification, linear regression interpretation, and an optional GitHub Codespaces environment with an AI coding agent.

Knowledge Points

2. Tidy data: principles and diagnosing messy structures

  • Tidy data has three principles:
    1. Each variable forms a column.
    2. Each observation forms a row.
    3. Each cell contains one value.
  • Data that has been collected or manually curated is not necessarily ready for analysis. A layout convenient for people to view may not preserve information or support reliable computer operations.
  • Hadley Wickham’s 2014 paper, Tidy Data, established the principles discussed in class. The instructor noted an earlier formulation concerning types and observational units, while emphasizing the one-value-per-cell principle in the lecture.
  • Useful signs that data may be messy include:
    • Column headers that encode values, such as years, income ranges, or weeks (WK1, WK2, etc.), rather than variable names.
    • A single column containing different kinds of measurements. For example, a count column mixing disease cases and population totals makes summaries such as means or maxima hard to interpret.
    • Column names that encode several variables, such as diagnosis, gender, and age in a name like m014.
    • Spreadsheet formatting—such as cell colors used to flag “good” or “bad”—that carries information not represented in the data itself. Such flags should be stored explicitly in a separate column.
  • Tidy data helps make filtering, grouping, calculations, and statistical summaries meaningful. The Tidyverse is a metapackage that loads several packages, including tidyr, which provides tools for tidying data.

3. Reshaping data with pivot_longer(), pivot_wider(), and separate()

  • pivot_longer() gathers multiple columns into a longer format, placing former column headers in a key column and their contents in a value column. It is useful when headers encode values, such as income brackets or weekly rankings.
  • pivot_wider() turns unique values in a category column into separate columns, filling them with values from another column. It can separate different measurement types, such as minimum and maximum temperature.
  • These operations are conceptually similar to arranging fields in an Excel pivot table. Which one—or whether both—is needed depends on the dataset and the intended analysis.
  • Patterned columns can be selected by position, excluded with !, or matched by prefixes and other patterns. For example, columns beginning with WK can be gathered, and the prefix can be removed to leave the week number.
  • After removing a text prefix, convert numeric-looking values to numeric types. Otherwise, values may sort alphabetically (1, 10, 11, 2) rather than numerically.
  • separate() or pivot_longer() can split compound names into distinct variables. When curating data, delimiters such as underscores or dashes provide “breadcrumbs” that make automated separation more reliable.
  • If multiple observations share the same identifiers, include another variable to distinguish their source or context, such as the observer. Otherwise, software may aggregate or average duplicate observations unintentionally.

Examples discussed

  • Pew Research religion and income data: Income ranges appear as column headers alongside religion names. Pivoting longer makes it easier to group by religion, calculate totals, and filter or compare frequencies.
  • Billboard rankings: Weekly columns such as WK1 through WK70+ can be reshaped into fields for song information, week, and ranking. A song can then occupy multiple rows—one per chart week—and be analyzed by week or artist. Missing weeks or rankings can be handled during the transformation.
  • WHO tuberculosis and census data: Headers may compress demographics or diagnosis details. Separating them into fields such as diagnosis, gender, age, and count makes demographic aggregation more direct.
  • Antarctic expedition measurements: Records by location and date can contain missing minimum or maximum temperature readings, which require explicit handling.

4. Data storage, formats, and missing values

  • Relational databases divide complex institutional data, such as hospital records, among specialized tables for patients, encounters, and procedures. Linking records with identifiers such as Patient ID avoids repeatedly storing the same demographic information.
  • CSV files are widely usable for data exchange and tutorials because they do not require proprietary software. Excel files are common in ad hoc workflows and can be read in R with packages such as readxl; enterprise systems generally use other data infrastructure.
  • Spreadsheet layouts that put time-series observations in columns can encounter software column limits. The lecture cited an NHS COVID-19 tracking failure in which daily counts arranged across columns exceeded a spreadsheet limit, leading to lost or overwritten data and disrupted predictive models.
  • In R, actual missing values are represented by NA, distinct from empty strings or special codes such as 99. is.na() returns logical values; because TRUE counts as 1 and FALSE as 0, summing is.na(column) counts missing values, while summing !is.na(column) counts non-missing values.

5. Tidyverse data manipulation

  • select() chooses columns, while filter() chooses rows that satisfy conditions. Columns can be selected by name or pattern—for example, names beginning with bill, ending in _text, or within a range such as Q21 through Q47. Multiple selections can be combined.
  • filter() conditions can use comparisons and logical operators. Use == to test equality; a single = is used for assignment or naming arguments. ! negates a condition, and | represents logical OR. Conditions can also be combined to require multiple criteria.
  • mutate() creates or transforms columns. For example, body mass in grams can be converted to kilograms by dividing by 1,000. For recoding or type conversion, creating an intermediate column can make it easier to verify the result before dropping the original with select().
  • The base R pipe, |> (available from R 4.0), chains operations in sequence and can replace the Tidyverse pipe %>%. It supports readable, vertically arranged workflows such as mutating, filtering, and selecting in order.
  • group_by() partitions data by one or more variables, and summarize() calculates statistics for each group. Summary functions include mean(), median(), min(), max(), and n(); multiple summaries can be produced in one call.

6. Dates and the Palmer Penguins dataset

  • When day values are spread across patterned columns, use pivot_longer() to gather them, extract the day from the column name, remove prefixes, convert the day to an integer, and retain the corresponding measurement.
  • Separate minimum and maximum measurements into distinct columns when a combined value column would make averages or extrema ambiguous.
  • Combine year, month, and day into a proper date or timestamp before date arithmetic. Computers can then calculate intervals between dates; time zones also need appropriate handling.
  • The Palmer Penguins dataset was used as a practice example. It contains 344 observations and eight columns, including species, island, sex, year, bill and flipper measurements, and body mass.
  • A two-step transformation can be easier to read and debug than a compact nested operation. Small differences in computing time are generally less important than code that can be understood and checked.

7. Visualization with ggplot2

  • ggplot2 expects tidy data. The aes() function maps columns to plot properties such as the x-axis, y-axis, and color; plots are built by adding layers with +.
  • Suitable basic plots depend on variable types:
    • Two continuous variables: scatter plot with geom_point().
    • One continuous variable: histogram.
    • Categorical variables: bar chart, which may be stacked or dodged.
  • geom_bar() uses stat = "count" to count observations for a categorical variable. geom_col() uses stat = "identity" and requires precomputed y-values. Use geom_col() when a summary table already contains counts or frequencies.
  • Labels, themes, and other styling can be added as layers.

8. Modeling: prediction targets and linear regression

  • A model needs clearly identified columns for its target and inputs. Inputs may be called predictors, independent variables, or Xs; the target may be called the response, dependent variable, or Y. Data cleaning and column selection can occur at different stages, and data work is iterative.
  • The target’s type determines the general prediction task:
    • A numeric target calls for regression, such as predicting age, an albumin score, or house price.
    • A categorical target calls for classification, such as predicting survival, disease status, or disease stage. Binary outcomes are common introductory examples.
  • In an R formula, the tilde separates the target from predictors: the target is on the left, and input variables are on the right. Predictors do not all need to be numeric; for example, a categorical variable can help predict a numeric outcome.
  • Visualize relationships before modeling when practical. A scatter plot can show the relationship between two numeric variables, though a model can include more predictors than can be displayed in a simple plot.
  • Linear regression models numeric outcomes. Its formula relates to y = mx + b: the target is y, predictors correspond to x terms, and coefficients represent slopes, with an intercept term. With multiple predictors, the model includes a coefficient for each.
  • In the Sacramento housing example, a coefficient of 138.5 for square footage indicates an expected increase of $138.50 in house price per additional square foot. Linear and logistic regression are commonly used in biostatistics partly because their results can often be described in interpretable terms. Logistic regression for categorical outcomes was introduced as upcoming material.
