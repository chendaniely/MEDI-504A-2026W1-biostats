Packages

What is tidy data?

[Image: Illustration of tidy data: each variable is a column, each observation is a row, each value is a cell.]

  1. Each variable is a column; each column is a variable
  2. Each observation is a row; each row is an observation
  3. Each value is a cell; each cell is a single value

Rules from R for Data Science (2e), chapter 5. Illustration by Julia Lowndes and Allison Horst, from the Openscapes blog (CC BY 4.0).

The original definition (2014)

The original Tidy Data paper from 2014 defines it a little differently:

  1. Each variable forms a column
  2. Each observation forms a row
  3. Each type of observational unit forms a table

The third rule is really about databases, where data is split into separate tables and joined back together. The newer definition replaces it with “each value is a cell”. We’ll come back to observational units in Lecture 2, in the Observational units section.

Tidy or not? (1 of 4)

country year rate
Afghanistan 1999 745/19987071
Afghanistan 2000 2666/20595360
Brazil 1999 37737/172006362
Brazil 2000 80488/174504898

Not tidy. The rate column has two values in each cell, the number of cases and the population.

Tidy or not? (2 of 4)

country 1999 2000
Afghanistan 745 2666
Brazil 37737 80488
China 212258 213766

Not tidy. The years are column headers, but they’re really values of a year variable.

Tidy or not? (3 of 4)

country year type count
Afghanistan 1999 cases 745
Afghanistan 1999 population 19987071
Afghanistan 2000 cases 2666
Afghanistan 2000 population 20595360

Not tidy. The count column mixes two different variables, cases and population.

Tidy or not? (4 of 4)

country year cases population
Afghanistan 1999 745 19987071
Afghanistan 2000 2666 20595360
Brazil 1999 37737 172006362
Brazil 2000 80488 174504898

Tidy! Each row is an observation, each column is a variable, and each cell has a single value.

Why bother?

[Image: Illustration: tidy datasets are all alike, but every messy dataset is messy in its own way.]

Once our data is tidy, we can use the same tools every time we summarize, plot, or model it.

Illustration by Julia Lowndes and Allison Horst (CC BY 4.0).

Five ways data gets messy

The Tidy Data paper lists five common ways data gets messy:

  1. Column headers are values, not variable names
  2. Multiple variables are stored in one column
  3. Variables are stored in both rows and columns
  4. Multiple types of observational units are stored in the same table
  5. A single observational unit is stored in multiple tables

We’ll go through the first three using the datasets from the paper. Problems 4 and 5 are about observational units, which we’ll cover in Lecture 2’s Observational units section.

Tidy the weeks

billboard_tidy <- billboard |>
  pivot_longer(
    cols = starts_with("wk"),
    names_to = "week",
    names_prefix = "wk",
    names_transform = list(week = as.integer),
    values_to = "rank",
    values_drop_na = TRUE # drop weeks the song was not on the chart
  ) |>
  # the date at a rank = the date it entered + (week - 1) weeks
  mutate(date = date.entered + (week - 1) * 7) |>
  arrange(artist, track, week) |>
  select(year, artist, track, time, week, rank, date)

Pivot longer, then wider

weather_tidy <- weather |>
  pivot_longer(
    cols = starts_with("d"),
    names_to = "day",
    names_prefix = "d",
    names_transform = list(day = as.integer),
    values_to = "temp",
    values_drop_na = TRUE
  ) |>
  mutate(date = make_date(year, month, day)) |>
  pivot_wider(
    names_from = element, # tmax and tmin become their own columns
    values_from = temp
  ) |>
  select(id, date, tmax, tmin) |>
  arrange(id, date)

mutate() gives back a new data frame and doesn’t change penguins. If we want to keep the result, we need to assign it (<-) to a variable.

Doing many steps at once

We can save each step as its own object,

penguins_1 <- mutate(penguins, body_mass_kg = body_mass / 1000)
penguins_2 <- filter(penguins_1, flipper_len > 190)
penguins_3 <- select(penguins_2, species, flipper_len, body_mass_kg)

or we can nest the function calls, but then we have to read them from the inside out.

penguins_nested <- select(
  filter(mutate(penguins, body_mass_kg = body_mass / 1000), flipper_len > 190),
  species, flipper_len, body_mass_kg
)

Visualization: ask a question, then answer it

[Image: Cartoon of fuzzy monsters exploring data with ggplot2.]

When we make a plot, we’re trying to answer a question about our data. A good plot answers that question clearly.

Artwork by Allison Horst (CC BY 4.0).

ggplot2: three parts

Every ggplot2 plot is built from the same parts:

  1. Aesthetic mappings, which map columns to visual properties (x, y, colour, fill)
  2. Geometric objects (geoms), which say how to draw them (geom_point(), geom_histogram(), geom_bar())
  3. Scales and labels for the axes, colours, and titles

We add each layer, one at a time, with +.

Scatter plot: two quantitative variables

Is a penguin’s body mass related to its flipper length?

ggplot(penguins, aes(x = flipper_len, y = body_mass)) +
  geom_point()

Rules of thumb

  • Answer one question per plot
  • Label axes, with units
  • Use colourblind-friendly palettes
  • Avoid pie charts, 3D, and tables of numbers when a plot will do

Two kinds of questions

When we want to predict something, the type of outcome tells us what kind of model to use.

  • Regression, when the outcome is quantitative. What will this house sell for? How heavy will this baby be at birth?
  • Classification, when the outcome is categorical. Will this patient’s cancer come back, yes or no?

Today we’ll fit a linear regression. On Wednesday we’ll fit linear and logistic regressions on medical data.

Models need tidy data

A model formula like price ~ sqft expects the data to have one row per observation (each house sale) and one column per variable (the price and the size), which is exactly what tidy data gives us.

Linear regression: the line of best fit

\[ \text{price} = \beta_0 + \beta_1 \times \text{sqft} \]

  • \(\beta_0\) is the intercept, where the line crosses the y axis
  • \(\beta_1\) is the slope, how much the price changes for each extra square foot

The “best” line is the one with the smallest squared vertical distances between the line and the data points.

Fit it with tidymodels

house_recipe <- recipe(price ~ sqft, data = Sacramento)

house_spec <- linear_reg() |>
  set_engine("lm") |>
  set_mode("regression")

house_fit <- workflow() |>
  add_recipe(house_recipe) |>
  add_model(house_spec) |>
  fit(data = Sacramento)

More than one predictor
