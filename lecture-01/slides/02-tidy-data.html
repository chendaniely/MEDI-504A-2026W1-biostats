Tidy data

Packages

library(tidyverse)

What is tidy data?

  1. Each variable is a column; each column is a variable
  2. Each observation is a row; each row is an observation
  3. Each value is a cell; each cell is a single value

Rules from R for Data Science (2e), chapter 5. Illustration by Julia Lowndes and Allison Horst, from the Openscapes blog (CC BY 4.0).

The original definition (2014)

The original Tidy Data paper from 2014 defines it a little differently:

  1. Each variable forms a column
  2. Each observation forms a row
  3. Each type of observational unit forms a table

The third rule is really about databases, where data is split into separate tables and joined back together. The newer definition replaces it with “each value is a cell”. We’ll come back to observational units at the end, in the optional Observational units section.

Tidy or not? (1 of 4)

country year rate
Afghanistan 1999 745/19987071
Afghanistan 2000 2666/20595360
Brazil 1999 37737/172006362
Brazil 2000 80488/174504898

Not tidy. The rate column has two values in each cell, the number of cases and the population.

Tidy or not? (2 of 4)

country 1999 2000
Afghanistan 745 2666
Brazil 37737 80488
China 212258 213766

Not tidy. The years are column headers, but they’re really values of a year variable.

Tidy or not? (3 of 4)

country year type count
Afghanistan 1999 cases 745
Afghanistan 1999 population 19987071
Afghanistan 2000 cases 2666
Afghanistan 2000 population 20595360

Not tidy. The count column mixes two different variables, cases and population.

Tidy or not? (4 of 4)

country year cases population
Afghanistan 1999 745 19987071
Afghanistan 2000 2666 20595360
Brazil 1999 37737 172006362
Brazil 2000 80488 174504898

Tidy! Each row is an observation, each column is a variable, and each cell has a single value.

Why bother?

Once our data is tidy, we can use the same tools every time we summarize, plot, or model it.

Illustration by Julia Lowndes and Allison Horst (CC BY 4.0).

Five ways data gets messy

The Tidy Data paper lists five common ways data gets messy:

  1. Column headers are values, not variable names
  2. Multiple variables are stored in one column
  3. Variables are stored in both rows and columns
  4. Multiple types of observational units are stored in the same table
  5. A single observational unit is stored in multiple tables

We’ll go through the first three using the datasets from the paper. Problems 4 and 5 are about observational units, which are in the optional Observational units section.

  pivot_longer(
    cols = -religion,
    names_to = "income",
    values_to = "frequency"

Tidy the weeks

billboard_tidy <- billboard |>
  pivot_longer(
    cols = starts_with("wk"),
    names_to = "week",
    names_prefix = "wk",
    names_transform = list(week = as.integer),
    values_to = "rank",
    values_drop_na = TRUE # drop weeks the song was not on the chart
  ) |>
  # the date at a rank = the date it entered + (week - 1) weeks
  mutate(date = date.entered + (week - 1) * 7) |>
  arrange(artist, track, week) |>
  select(year, artist, track, time, week, rank, date)

Pivot longer, then wider

weather_tidy <- weather |>
  pivot_longer(
    cols = starts_with("d"),
    names_to = "day",
    names_prefix = "d",
    names_transform = list(day = as.integer),
    values_to = "temp",
    values_drop_na = TRUE
  ) |>
  mutate(date = make_date(year, month, day)) |>
  pivot_wider(
    names_from = element, # tmax and tmin become their own columns
    values_from = temp
  ) |>
  select(id, date, tmax, tmin) |>
  arrange(id, date)
